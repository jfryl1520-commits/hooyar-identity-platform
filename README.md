# هویار | سامانه مدیریت هویت

هویار یک نمونه‌ی فارسی و راست‌چین برای مدیریت پرونده‌های هویتی و بررسی کارشناسی است. داشبورد زنده، صف بررسی، آمار ثبت پرونده و مدیریت اطلاعات را روی API و SQLite موجود ارائه می‌کند.

> این مخزن یک نمونه‌ی نرم‌افزاری است؛ اتصال به ثبت احوال، استعلام سند، پیامک، تشخیص چهره یا احراز هویت قانونی در آن پیاده‌سازی نشده است. برچسب «تأیید شده» فقط نتیجه‌ی بررسی داخلی کارشناس را نشان می‌دهد. پیش از استفاده‌ی واقعی، ارزیابی امنیتی، سیاست نگه‌داری داده، کنترل دسترسی سازمانی و اتصال رسمی لازم است.

## استقرار روی Netlify

پروژه از نسخه‌ی ۱.۲ روی Netlify هم قابل استقرار است. اپ Express همچنان در یک Netlify Function اجرا می‌شود و صفحه‌های ثابت از پوشه‌ی `public` منتشر می‌شوند؛ کد اصلی تغییری نکرده.

۱. مخزن را در Netlify متصل کنید. `netlify.toml` موجود است، پس نیازی به تنظیم دستی «پوشهٔ انتشار» نیست (خودکار `public` تشخیص داده می‌شود).

۲. یک دیتابیس پایدار بسازید. سامانه به‌صورت پیش‌فرض از SQLite روی فایل محلی استفاده می‌کند و فایل‌سیستم Netlify Functions موقتی است، پس بدون دیتابیس بیرونی داده‌ها با هر اجرای دوباره از دست می‌روند (و `better-sqlite3` به‌عنوان ماژول native قابل bundle کردن نیست). یک دیتابیس رایگان در [Turso](https://turso.tech) بسازید — SQLite کاملاً سازگار است.

۳. این متغیرهای محیطی را در **Site settings → Environment variables** قرار دهید:

| متغیر | مقدار | لازم؟ |
|---|---|---|
| `JWT_SECRET` | رشته‌ی تصادفی حداقل ۳۲ نویسه (مقدار نمونه رد می‌شود) | بله |
| `ADMIN_USERNAME` | نام کاربری مدیر آغازین | بله |
| `ADMIN_PASSWORD` | گذرواژه‌ی حداقل ۱۲ نویسه | بله |
| `TURSO_DATABASE_URL` | نشانی دیتابیس Turso، مثل `libsql://...` | بله |
| `TURSO_AUTH_TOKEN` | توکن دسترسی Turso | بله |
| `MFA_ENCRYPTION_KEY` | رشته‌ی تصادفی برای رمزنگاری کلید TOTP | توصیه‌شده |
| `DEMO_PASSWORD` | گذرواژه‌ی مشتریان نمونه | توصیه‌شده |

۴. Deploy کنید. آدرس صفحه‌ی اصلی و هر دو صفحهٔ ورود بدون پیشوند `/public/` باز می‌شوند و همه‌ی مسیرهای `/api/*` و `/health` کار می‌کنند.

نکته: جدا از `JWT_SECRET`، مقدار `DEPRECATED` که در تنظیمات سایت وجود دارد بی‌اثر است و حذفش چه مشکلی ندارد.

## استقرار روی Railway / Render (ساده‌تر، بدون دیتابیس بیرونی)

اگر ترجیح می‌دهید کد را دست‌نخورده و با دیسک پایدار اجرا کنید، `Procfile` برای همین سرویس‌ها نوشته شده: یک Volume به سرویس وصل کنید، `DATABASE_PATH` را روی مسیری داخل آن Volume تنظیم کنید و متغیرهای `JWT_SECRET`، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را تعریف کنید. در این حالت هیچ متغیر `TURSO_*` لازم نیست.

## شروع سریع

1. Node.js 18 یا جدیدتر را نصب کنید.
2. وابستگی‌ها را نصب کنید: `npm ci`
3. `.env.example` را به `.env` کپی کنید و مقادیر محلی را تنظیم کنید. برای گذرواژه‌ی مدیر، یک مقدار تصادفی با حداقل ۱۲ نویسه انتخاب کنید.
4. سرور را اجرا کنید: `npm start`
5. داشبورد را در `http://localhost:3000/admin-login.html` باز کنید.

پایگاه داده‌ی محلی به‌صورت خودکار در `database.sqlite` ساخته می‌شود. این فایل و فایل `.env` عمداً در Git نادیده گرفته می‌شوند. حساب مدیر آغازین فقط وقتی ساخته می‌شود که `ADMIN_USERNAME` و `ADMIN_PASSWORD` تنظیم شده باشند.

هنگام اولین اجرا روی یک دیتابیس خالی، شش پرونده‌ی نمایشی و پنج درخواست خدمت ساخته می‌شود. ورود مشتریان نمونه با موبایل موجود در پرونده و گذرواژه‌ی `DEMO_PASSWORD` (پیش‌فرض `123456`) انجام می‌شود؛ در هر محیط عمومی این مقدار را تغییر دهید.

### نکات امنیتی مهم

- **دسترسی مشتری محدود است:** پنل شهروندی فقط فیلدهای پایه‌ی خود پرونده را نشان می‌دهد. قومیت، دین، گروه خون، شماره مدرک، یادداشت داخلی و سابقه‌ی فعالیت فقط در کنسول مدیر قابل مشاهده است.
- **ورود دومرحله‌ای قابل دور زدن با تغییر رمز نیست:** حساب مدیر با MFA فعال هرگز تنها با گذرواژه توکن کامل نمی‌گیرد. غیرفعال‌سازی MFA فقط از مسیر `POST /api/auth/admin/mfa/disable` با گذرواژه‌ی فعلی و یک کد یک‌بارمصرف معتبر ممکن است.
- **کلید رمزنگاری TOTP:** راز TOTP مدیر با کلید AES مستقل (`MFA_ENCRYPTION_KEY`) یا در نبود آن از `JWT_SECRET` رمز می‌شود. برای استقرار واقعی `MFA_ENCRYPTION_KEY` را تنظیم کنید تا چرخاندن `JWT_SECRET` همه‌ی مدیران را قفل نکند.
- **پشت پراکسی:** `TRUST_PROXY=1` (یا مقدار مناسب شبکه) تنظیم کنید، وگرنه محدودیت تلاش ورود برای همه‌ی کاربران یک سبد مشترک خواهد داشت.
- **صفحه‌ی فرود** فقط آمار تجمیعی (تعداد کل، تأییدشده، درخواست باز) را از `/api/admin/public-summary` می‌گیرد و هیچ داده‌ی شخصی نمایش نمی‌دهد.

## امکانات فعلی

- داشبورد فارسی با آمار پرونده‌ها و نمودار ثبت ماهانه
- صف پرونده‌های منتظر بررسی و اقدام تأیید داخلی
- جست‌وجو، فیلتر و صفحه‌بندی پرونده‌ها
- ایجاد پرونده از داشبورد با شناسه‌ی یکتا
- ورود مدیر و مشتری با هش گذرواژه و توکن JWT
- ورود دومرحله‌ای مدیر با TOTP، رمزنگاری کلید بازیابی‌شده در دیتابیس و جلوگیری از استفاده‌ی مجدد از کد
- محدودیت تلاش ورود و سربرگ‌های پایه‌ی امنیت مرورگر
- ثبت رویدادهای مدیریتی در گزارش فعالیت
- رابط واکنش‌گرا برای نمایشگر بزرگ و موبایل
- ثبت درخواست خدمت توسط مشتری و پیگیری وضعیت آن در پنل کاربری
- مسیر سلامت `/health` و پشتیبانی از مسیر دیتابیس قابل تنظیم برای volume پایدار

## معماری

- سرور: Node.js و Express
- پایگاه داده: SQLite با `better-sqlite3`
- رابط کاربری: HTML، CSS و JavaScript راست‌چین
- ورود: JWT و bcrypt

## متغیرهای محیطی

نمونه در [.env.example](.env.example) قرار دارد. `JWT_SECRET` باید مقدار تصادفی قوی و پایدار داشته باشد و برابر با مقدار نمونه نباشد (سرور مقدار نمونه را رد می‌کند). برای رمزنگاری رازهای TOTP از `MFA_ENCRYPTION_KEY` مستقل استفاده کنید؛ در نبود آن، کلید از `JWT_SECRET` مشتق می‌شود و چرخاندن آن کلیدهای TOTP را نامعتبر می‌کند. برنامه به‌صورت پیش‌فرض فقط روی `127.0.0.1` گوش می‌دهد. برای استقرار پشت پراکسی امن، `HOST` را آگاهانه تنظیم کنید، HTTPS فعال باشد، و دسترسی شبکه و پشتیبان‌گیری پایگاه داده محدود شود.

## مسیرهای اصلی API

- `POST /api/auth/admin/login` — ورود مدیر
- `POST /api/auth/admin/verify-mfa` — تکمیل ورود دومرحله‌ای
- `POST /api/auth/admin/mfa/setup` و `POST /api/auth/admin/mfa/enable` — راه‌اندازی TOTP مدیر
- `GET /api/admin/stats` — آمار داشبورد
- `GET /api/admin/customers` — جست‌وجو و فهرست پرونده‌ها
- `GET /api/admin/customers/:id` — جزئیات پرونده
- `POST /api/admin/customers` — ایجاد پرونده
- `PATCH /api/admin/customers/:id/status` — تغییر وضعیت داخلی
- `GET /api/admin/logs` — گزارش فعالیت
- `GET /api/admin/public-summary` — آمار تجمیعی عمومی (بدون توکن)
- `POST /api/customer/services` — ثبت درخواست خدمت توسط مشتری (محدود به ۸ درخواست در ۱۰ دقیقه)
- `GET /health` — بررسی سلامت سرویس

تمام مسیرهای `/api/admin` به توکن مدیر نیاز دارند.

برای استقرار روی Railway، یک Volume به سرویس متصل کنید و `DATABASE_PATH` را روی مسیری داخل mount، مانند `/data/database.sqlite` تنظیم کنید تا دیتابیس SQLite بعد از استقرار مجدد باقی بماند. متغیرهای `JWT_SECRET`، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را در تنظیمات سرویس تعریف کنید؛ اسرار نمونه را در محیط واقعی استفاده نکنید.
